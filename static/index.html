Tokenization

Your message is wrapped in the chat template, then split into word pieces called tokens. Each token gets an id.
Are these numbers real?

Yes. Each token runs on this computer's GPU (Apple MPS, float32) with PyTorch hooks on every sub-operation, including a custom attention function that exposes RoPE, the raw QKᵀ scores, the softmax and the weighted sum. The hooks keep the exact tensors the GPU produced. The browser replays that recording on a scaled clock.

Timing: GPU timing events measure each word's true GPU time without stalling the GPU. Ops that share one GPU command buffer can't be told apart by events, so that total is split across ops in proportion to their cost measured in a separate synced run. Expert mode shows the raw numbers.

Weights: matrices show a 128×128 grid of the actual weights; hovering fetches the exact weights under the cursor; the 🔬 view redoes a full dot product in float64 and checks it against the GPU's answer.

"Why this word?" is an exact decomposition of the final score (it adds up to the logit to 4 decimals), with the final normalization scale held at its real value. Knockouts really re-run the model with those parts zeroed.

Illustrative only: the left-to-right sweep order, and the "parallel tiles" sweep, which shows the idea of the GPU's cores working at once but not the real MPS kernel's tile layout.
